# 07. 회원관리 심화 설계 — 관리자 사이드 × 회원 사이드

> 회원관리는 예약관리와 함께 **2대 핵심 기둥**. `02 §1`이 관리자 CRUD 위주로 얕아
> 양면(관리자/회원) 전체 생애주기를 이 문서에서 상세화한다.
> 전제: **단일 스튜디오 · 단일 반응형 웹앱(PWA)+역할기반 뷰**. 표기 `[MVP]/[v1]/[v2+]`.

---

## 0. 두 사이드 한눈에

```
                          ┌──────────────── 같은 사람(휴대폰번호로 동일성) ───────────────┐
   관리자 사이드 (운영자/강사)                                          회원 사이드 (수강생)
   ─────────────────────────                                          ─────────────────────
   회원 유입·등록(4경로)        ─ 초대/승인 ─                          가입·온보딩(셀프)
   등록대기 승인 큐            ◀───── 등록 요청 ─────                  센터 연결(검색→요청)
   회원 360° 상세              ─ 발급/수정 즉시 반영 ─▶                마이페이지(내 수강권/이력)
   수강권 발급·정지·연장                                              예약/취소/대기
   상담·리드 관리                                                     내 운동기록(v1)
   검색·필터·세그먼트                                                 알림 설정 / 1:1 문의
   메시지·재등록 캠페인        ─ 알림톡/푸시 ─▶                        동의 관리 / 탈퇴
   개인정보·동의·권한                                                 멀티센터(v2+)
```

핵심 원칙: **회원 데이터는 하나, 보는 창이 둘.** 관리자가 발급한 수강권은 회원 마이페이지에
즉시 반영되고, 회원이 올린 등록 요청은 관리자 승인 큐로 들어온다.

## 1. 회원 정체성·계정 모델 (양면 공통 — 가장 먼저 합의할 것)

소형 단일 스튜디오 기준으로 **단순화**하되, 앱 셀프가입과 운영자 등록이 충돌하지 않게 한다.

- **★ 스튜디오 게이트(필수 원칙)**: 회원 계정은 **반드시 실제 스튜디오에 등록·승인되어야** 서비스 사용 가능.
  스튜디오메이트와 동일한 구조. 아하루식 *"센터 없이 단독 사용(운동일지·커뮤니티 등)"* 은 **채택하지 않음**
  (관리·정산·데이터 정합성 우선, 유령 계정 방지).
- **1 사람 = 1 로그인 계정(휴대폰 인증) + 스튜디오 회원 프로필 1개**
- **매칭 키 = 휴대폰 번호.** 운영자가 먼저 등록(초대) → 회원이 같은 번호로 셀프 가입하면 **자동 연결(병합)**.
- 회원 상태를 **3축으로 분리**(현재 단일 `status`의 한계 해결):

| 축 | 값 | 의미 | 누가 변경 |
|----|----|------|----------|
| `account_status` | `invited` / `active` / `withdrawn` | 로그인 계정 활성 여부 | 회원(가입/탈퇴) |
| `approval_status` | `pending` / `approved` / `rejected` | 스튜디오 등록 승인 | 관리자 |
| `lifecycle_status` | `active` / `dormant` / `expiring` / `churn_risk` | 영업·CRM 상태(자동 태깅 `[v1]`) | 시스템 |

> 예: 운영자가 등록 → `invited`+`approved`. 회원이 셀프가입 → `pending`(운영자 승인 대기).
> 데이터모델 반영은 [06 §2.2](06-data-model.md) 갱신분 참조.

## 2. 관리자 사이드 (운영자 / 강사)

### 2.1 회원 유입·등록 — 4경로 `[MVP]`(③④는 일부 v1)
| 경로 | 흐름 | 단계 |
|------|------|------|
| ① 운영자 직접 등록 | 이름+연락처 입력 → **초대 문자/링크 자동 발송** → 회원 셀프 활성화 | `[MVP]` |
| ② 회원 셀프가입 후 승인 | 회원이 가입·센터 등록요청 → **관리자 승인 큐**에서 승인/거절 | `[v1]` |
| ③ 엑셀 일괄 등록 | 양식 다운로드 → 입력 → 업로드 → 검증 후 일괄 생성 | `[MVP]` (갈아타기 장벽 제거 = 필수) |
| ④ 타 솔루션 데이터 이전 | 기존 데이터 매핑·임포트(반자동/지원) | `[v1]` |

### 2.2 등록 대기 승인 큐 `[v1]` (MVP는 운영자 초대 단방향)
- 탭: **전체 회원 / 등록 대기 / 탈퇴**
- 대기 목록 → 회원 선택 → **승인 / 거절** (승인 시 회원에게 알림, `approval_status=approved`)
- 중복 가입(같은 번호) 자동 감지 → 기존 프로필과 병합 제안

### 2.3 회원 360° 상세 `[MVP]` (핵심 화면)
한 화면에서 회원의 모든 것:
| 블록 | 내용 | 단계 |
|------|------|------|
| 기본 정보 | 이름·연락처·성별·생년·사진·가입일 | `[MVP]` |
| 보유 수강권 | 종류·잔여/총·유효기간·상태(active/paused/expired) | `[MVP]` |
| 예약·출석 이력 | 예정/과거, 출석/결석/노쇼, **출석률** | `[MVP]` |
| 결제·미수금 | 판매·결제 내역, 미수금 잔액 | `[MVP]` |
| 메모·상담 이력 | 운영자 메모, 상담 기록(타임라인) | `[MVP]` |
| 태그 | VIP/산전·산후/재활 등 | `[v1]` |
| 건강·운동 기록 | 체형·통증·목표·세션노트 | `[v1]` (추후 디벨롭) |
| 알림 발송 이력 | 이 회원에게 보낸 메시지 | `[v1]` |
> 상세에서 바로: **수강권 발급 / 정지·재개 / 연장 / 메시지 발송 / 상담 추가**.

### 2.4 검색·필터·세그먼트 `[MVP]`
- 빠른 검색: 이름 / 연락처
- 필터: **수강권 상태**(유효·만료·없음) · 등록일(기간) · 최근 방문(활성/휴면) · 태그
- 세그먼트 저장 → 재등록·이탈방지 캠페인 대상으로 연결(→ `06` campaign, `[v1]`)

### 2.5 회원 상태 자동 태깅 `[v1]`
- `expiring`: 수강권 만료 D-N 또는 잔여 N회 이하
- `dormant`: 최근 방문 N일 초과
- `churn_risk`: 출석 빈도 급감(직전 대비 −X%)
- → 대시보드 위젯 + 캠페인 타겟으로 자동 연결

### 2.6 상담·리드 관리 `[v1]`
- 미등록 잠재고객(상담 예약)도 관리: 상담 일정 생성(이름·연락처·메모) → 상담 이력 → **회원 전환** 추적
- 전환율(상담 → 등록) 통계

### 2.7 회원 커뮤니케이션 `[MVP]`~`[v1]`
- 개별: 회원 상세에서 메시지/알림톡 발송, (선택) 카카오톡 연락
- 단체: 세그먼트 대상 공지·프로모션 `[v1]`
- 자동: 예약확정·리마인더·수강권 만료·생일 → `06` campaign/message_log

### 2.8 개인정보·동의·권한 `[MVP]`~`[v1]`
- **동의 이력**: 이용약관·개인정보처리방침·마케팅 수신(각 동의 시각 기록) `[v1]`
- **민감정보(건강기록)**: 암호화 저장 + 접근 로그 `[v1]`
- **권한별 노출 범위**:

| 역할 | 회원 정보 접근 |
|------|----------------|
| 오너 | 전체 |
| 매니저 | 전체(설정/정산 일부 제한) |
| 강사 | **담당 회원만** + 본인 세션노트 |
| 회원 | **본인만** |

- 탈퇴 처리: 회원 요청/운영자 처리 → 보존 의무 데이터(정산·세무)는 분리 보존, 그 외 파기

## 3. 회원 사이드 (수강생 — 셀프서비스)

> 단일 반응형 웹앱의 **회원 역할 뷰(PWA)**. 네이티브앱은 리텐션 검증 후.

### 3.1 가입·온보딩 `[MVP]`
- 진입(MVP): 운영자 **초대 링크/문자**. (매장 QR 셀프가입은 `[v1]`)
- 방식: 휴대폰 인증 기반(소셜/이메일은 선택) — **본인 인증 필수**(중복·도용 방지)
- **약관·개인정보 수집 동의 필수**(법적, MVP) — 가입 첫 화면
- 초대로 들어온 경우: 번호 매칭으로 **기존 프로필 자동 연결**(재입력 없음)

### 3.2 센터 연결 `[MVP]` (★ 스튜디오 게이트 — 소형 단일 스튜디오 경량화)
- **센터에 등록·승인되지 않으면 서비스 사용 불가**(예약·마이페이지 전부). 가입만 하고 센터 미연결 상태는 "이용 불가 + 등록 안내"만 노출. → 스튜디오메이트형.
- 우리 범위는 단일 스튜디오라 아하루식 "센터 검색 마켓"은 **불필요** → **초대/가입 링크가 곧 그 센터**로 귀속
- 회원 셀프가입(승인 대기) 케이스만 `approval_status=pending` → 승인 후 이용
- 멀티센터(한 회원이 여러 지점)는 `[v2+]`

### 3.3 마이페이지 `[MVP]` (회원이 보는 360°)
| 블록 | 내용 | 단계 |
|------|------|------|
| 내 프로필 | 이름·연락처·사진 | `[MVP]` |
| **내 수강권** | 잔여/총 횟수·유효기간·사용 내역 | `[MVP]` |
| 결제 내역 | 결제일·금액·수단·할인 | `[MVP]` |
| 내 예약 현황 | 예정 수업·대기·취소 | `[MVP]` |
| 출석 이력 | 과거 출석/결석/노쇼 | `[v1]` |
| 내 운동기록 | 세션노트·자세(보기) | `[v1]` (추후 디벨롭) |

### 3.4 내 정보·계정 관리 `[MVP]`
- 프로필 수정(이름·사진·연락처), 비밀번호 변경(이메일 가입 시)
- 로그아웃 / **회원 탈퇴**(파기 안내 후)

### 3.5 예약/취소/대기 `[MVP]`
- 예약 모듈(`02 §2`)과 연결: 타임테이블에서 예약·취소, 정원 시 대기, 자동 승급 알림(`[v1]`)
- 수강권 잔여·유효기간에 따른 예약 가능 여부 즉시 표시

### 3.6 알림 설정 `[MVP]`
- 항목별 ON/OFF: 예약 확정·취소 / 수업 리마인더 / 수강권 만료·잔여 / 공지
- 채널: 푸시(PWA 웹푸시) + 카카오 알림톡(`[v1]`)

### 3.7 소통·문의 `[MVP]`~`[v1]`
- 공지사항 보기, 1:1 문의(`[MVP]`)
- (보류) 커뮤니티 — 추후 디벨롭

### 3.8 동의 관리 `[v1]`
- 마케팅 수신 동의 ON/OFF, 약관/개인정보 처리방침 열람, 동의 이력 확인

## 4. 양면 동기화 시나리오 (정합성 체크)

| 이벤트 | 관리자 사이드 | 회원 사이드 |
|--------|--------------|------------|
| 운영자가 수강권 발급 | 360°에 즉시 표시 | 마이페이지 "내 수강권"에 즉시 반영 + 알림 |
| 회원이 셀프 가입 | **등록 대기 큐**에 등장 | "승인 대기" 상태 표시 |
| 운영자가 승인 | 회원 활성화 | 알림 수신 + 예약 가능해짐 |
| 회원이 예약/취소 | 타임테이블·예약현황 갱신 | 내 예약 현황 갱신 |
| 출석 처리(차감) | 출석률·잔여 갱신 | 잔여 횟수 −1 반영 |
| 수강권 만료 임박 | `expiring` 태깅 + 캠페인 대상 | 만료 알림 수신 |
| 회원 탈퇴 | 탈퇴 회원 탭으로 이동(보존데이터 분리) | 계정 파기 안내 |

## 5. 데이터모델 영향 (→ 06 반영)

신규/변경 (자세 정의는 [06 §2.2](06-data-model.md)):
- `member` 확장: `account_status`, `approval_status`, `lifecycle_status`(기존 status 대체), `auth_user_id`(로그인 계정 링크), `invited_at`
- 신규 `member_consent`(동의 이력): member_id, type(terms/privacy/marketing), agreed, agreed_at `[v1]`
- 신규 `consultation`(상담·리드): studio_id, name, phone, status(lead/booked/converted), memo, converted_member_id `[v1]`
- `member_memo`/상담 타임라인: member 상세 메모를 이력으로 (간단히 `member` memo + 별도 note 테이블 검토)
- 권한: 강사=담당회원만 노출 → 쿼리 레벨 스코프(담당 class_session 기반)

## 6. MVP 회원관리 범위 (리뷰 반영 재조정)

**포함:** 운영자 초대 등록(①) · 엑셀 일괄등록(③) · 회원 360° · 검색/필터 · 수강권 발급/**홀딩**/연장 · **미수금** · 개별 메시지 · 가입/온보딩(**약관·개인정보 동의 필수**) · 마이페이지(수강권·결제·예약) · 내정보/계정 · 알림설정 · 1:1문의 · **데이터 내보내기(CSV)**

**v1:** 셀프가입(②)+**승인큐**+번호병합 · 매니저롤·**강사 담당회원 스코프** · 자동 태깅 · 상담/리드 · 동의 이력관리 · 단체 캠페인 · 출석 이력 노출 · 데이터 이전(④)

**추후 디벨롭:** 건강·운동 기록/자세, 커뮤니티, 멀티센터, 가족/지인 연결
