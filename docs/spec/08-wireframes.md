# 08-wireframes.md — 주요 화면 와이어프레임 설명

> **목적**: 핵심 화면 15종의 레이아웃(ASCII) · 구성요소 · 인터랙션 · 데이터소스를 서술하여, IA(`07-ia.md`)와 ERD(`11-erd.md`)·API(`12-api.md`) 사이를 잇는 화면 명세를 제공한다. 모든 필드명·enum 라벨·역할명은 [`00-canon.md`](./00-canon.md)를 글자 단위로 따른다.

본 문서는 시각적 디자인(색/폰트/픽셀)이 아니라 **정보 배치·동작·데이터 출처**를 정의한다. 각 화면 말미에 [`_source-requirements.md`](./_source-requirements.md) §18의 UX 원칙(원장 **10초**, 관리자 **3클릭**, 회원 **30초**)을 어떻게 충족하는지 명시한다.

---

## 0. 공통 규칙 (모든 화면 적용)

### 0.1 표기 약속
- ASCII 박스에서 `[버튼]`=클릭 액션, `▼`=드롭다운, `◉/○`=라디오, `☑/☐`=체크, `«»`=토글, `▸`=펼침/접힘, `🔴🟡🟢`=상태 뱃지(텍스트 라벨 병기).
- 모든 금액은 정수(원) 표시, 천단위 콤마. 시각은 스튜디오 타임존(기본 `Asia/Seoul`) 기준 표시(저장은 UTC, §1.4).
- 화면 데이터는 항상 `tenant_id` + `studio_id` 필터가 묵시적으로 적용된다(다중 테넌트 격리, §1.2).

### 0.2 공통 레이아웃 셸 (관리자 웹)

- 글로벌 바: 스튜디오 전환(`studios`), 알림 벨(`notifications` where status=`scheduled`/`sent`), 사용자 메뉴(`users.role` 라벨 표시).
- 사이드바 항목은 **역할(role)별로 노출 제어**된다(§5 RBAC). 예: `instructor`는 결제·비용·수익분석·정산/매칭 메뉴 비노출. `accountant`는 수강권 발급·예약 메뉴 읽기 전용.
- 데이터소스: 사이드바 권한 = `permissions`(role_code × resource × action), 스튜디오 목록 = `studios`.

### 구성요소 · 데이터소스
| 영역 | 핵심 지표 | 데이터소스(canon) |
|---|---|---|
| ① 오늘 운영 | 오늘수업/예약/잔여석 | `class_sessions`(start_at=오늘), `reservations`(status=`booked`), capacity−booked |
| ① | 체험예약 | `class_sessions` where class_type=`trial` |
| ① | 노쇼위험 | `members` tag=`no_show_risk` (§3.17) |
| ① | 만료예정 | `passes` where expire_date≤오늘+`expiring_alert_days`(7일) |
| ① | 미수금 | `payments` where payment_status in (`receivable`,`partial`) |
| ① | 신규상담 | `leads` where lead_status=`new_inquiry`, inquiry_date=오늘 |
| ② 매출 | 총/순/유형별/신규·재등록 | `revenue_records`(선택 basis 합산, §4.3) |
| ③ 비용 | 총/고정/변동/카테고리 | `expense_records`(cost_type별·expense_category별 합) |
| ④ 수익 | 영업이익/률/잔액/미입금/미수금 | §4.4 산식: 순매출−총비용 / `bank_accounts.balance_amount` / `card_sales`(stage≠`deposited`) |

### 인터랙션
- **매출기준 토글** `«결제기준/소진기준»`: `revenue_records.revenue_basis`(`payment`/`consumption`)를 전환 → ②④ 수치 즉시 재계산(중복 합산 금지, 기준별로만 합산, §4 주의).
- 각 카드의 `[보기]`는 해당 필터가 걸린 목록 화면으로 이동(예: 미수금 → 화면 9).
- 기준월 드롭다운으로 과거 월 비교.

### UX 원칙 충족 (원장 10초)
- 4영역이 단일 스크린에 집약 → **스크롤 없이 오늘 운영 + 이번 달 수익을 한눈에**. 영업이익·영업이익률·월말예상이익을 ④에 굵게 배치하여 "이번 달 얼마 벌었나"를 즉시 인지.
- 회계 비전문가용 표현: "총매출 − 환불 = 순매출", "순매출 − 총비용 = 영업이익"을 카드에 산식 라벨로 노출.

### 구성요소 · 데이터소스
- 셀 = `class_sessions`(start_at∈주간범위). 표시: class_type 라벨(`personal`=1:1 / `group`=그룹 / `trial`=체험), 강사명(`instructor_staff_id`→`staff`), 예약현황 `booked/capacity`.
- 색/뱃지 = `session_status`(§3.4: `scheduled`/`open`/`closed`/`canceled`/`completed`).
- `★` = 해당 세션에 `waitlists`(status=`waiting`) 존재. `대체!` = `substitute_staff_id` 채워짐.
- 필터: 룸(`rooms`), 강사(`staff`).

### 인터랙션
- 셀 클릭 → 화면 3(세션 상세). `[+수업]` → 단일 세션 생성(또는 `class_templates` 기반 회차 생성).
- 드래그(2차)로 시간 이동 시 `class_sessions.start_at`/`end_at` 변경 → 변경은 `audit_logs`(action=`update`).
- 정원 초과 셀(🔴) 진입 시 대기열 관리 패널 노출.

### UX 원칙 충족 (관리자 3클릭)
- 주간 뷰 → 셀 클릭(1) → 출결 패널에서 회원 체크(2) → 저장(3)으로 출석 처리 완료.

## 화면 3. 예약/세션 상세 (출결 처리)

> 역할: 출결 처리=`owner`/`manager`/`info_staff`/`instructor`(담당). 차감은 `pass_transactions` 생성으로 기록.

### 레이아웃
```
┌──────────────────────────────────────────────────────────────────────────┐
│ ◀ 세션 상세    그룹레슨 · 2026-06-12(금) 10:00~10:50 · 1번룸 · 윤강사     │
│ 상태: 🟡 closed(예약마감)   정원 8 · 예약 7 · 대기 2   [세션수정][폐강]   │
├──────────────────────────────────────────────────────────────────────────┤
│ 예약자 (7)                                          차감시점: 출석 시       │
│ ┌──┬─────────┬──────────┬───────────┬───────────────┬──────────────────┐ │

│ └──┴─────────┴──────────┴───────────┴───────────────┴──────────────────┘ │

└──────────────────────────────────────────────────────────────────────────┘
```

### 구성요소 · 데이터소스
- 헤더 = `class_sessions`(+ room/instructor 조인), `session_status`.
- 예약자 행 = `reservations`(class_session_id), `reservation_status`(§3.5), 잔여=`passes.remaining_count`.
- 출결 라디오 = `attendance_status`(§3.6: `attended`/`late`/`absent`/`no_show`/`excused`).
- 차감시점 라벨 = 스튜디오 정책 `deduct_timing`(`on_booking`/`on_attend`, §6.1).
- 대기자 = `waitlists`(status=`waiting`, position 순). 자동전환 = `waitlist_auto_promote`.

### 인터랙션 · 산식
- `[출석확정]` → `attendance` 생성(status=`attended`) + 정책이 `on_attend`이면 `pass_transactions`(reason=`deduct_attend`, delta=−1, balance_after=잔여−1) 생성, `passes.remaining_count` 감소.
- 노쇼 처리 → `no_show_deduct`=true면 동일하게 −1 차감(reason 메타에 노쇼 표시).
- `[복구]` → `pass_transactions`(reason=`manual_restore`, delta=+1). 모든 차감/복구는 `audit_logs`(action=`pass_adjust`) 기록.
- `[대리 예약 추가]` → 회원 검색 후 `reservations`(is_self_booked=false) 생성.
- 소진기준 매출 연동: 차감 트랜잭션 발생 시 `revenue_records`(basis=`consumption`, amount=`passes.unit_price_amount`, class_type/instructor 채움)가 자동 생성(§4.2).

### UX 원칙 충족 (관리자 3클릭)
- `[전체 출석확정]` 1클릭으로 정상 출석자 일괄 처리. 잔여부족(🟡) 회원은 인라인 경고로 즉시 식별.

### 구성요소 · 데이터소스
- 행 = `members`. 상태 = `member_status`(§3.1: 신규문의~재등록완료). 담당 = `assigned_staff_id`→`staff`.

### 인터랙션
- `[+회원]` → 화면 7로 통하는 신규 등록 모달(이름·연락처·성별·유입경로). `[문자발송]` → 선택 회원에 `notifications` 일괄 예약.

```
│ 06-09 │출금 │88,000  │스타벅스   │분류 필요           │ ▼선택 │[저장]│
├──────────────────────────────────────────────────────────────────────────┤
│ 선택 거래 [일괄 확정]   ·   "이 거래처 분류를 규칙으로 저장" ☑            │
└──────────────────────────────────────────────────────────────────────────┘
```

### 구성요소 · 데이터소스
- 통장 큐 = `bank_transactions`(is_matched=false). 금액(입금+/출금−), direction, counterparty_name.
- 추천 매칭: 입금→`payments`(금액/입금자명 일치) 또는 `card_sales` 입금배치; 출금→`transaction_matching_rules`(거래처명 패턴) 매핑.
- 분류 = `match_target`(§3.19: `revenue`/`expense`/`transfer`/`etc`). 카드매출 입금은 `reconciliation_stage`=`deposited`(§3.21)로 갱신.
- 카드지출 탭 = `card_expenses` → `expense_records` 분류.

### 인터랙션 · 산식
- `[확정]` → `bank_transactions.match_target`+`matched_ref_type/id` 설정, is_matched=true. 결제 매칭이면 `payments`(입금확정), 카드입금이면 `card_sales`(stage→`deposited`, `bank_transaction_id` 연결) + 통장 잔액 동기화.
- **규칙 학습**: `☑ 규칙으로 저장` → `transaction_matching_rules` 생성(pattern=거래처명, target_match, expense_category) → **다음 동일 거래처부터 자동 분류**(원본 §7·§18). 모든 매칭은 `transaction_reconciliation_logs`(action=`manual_matched`/`auto_matched`) 기록.
- 미입금 카드매출 = Σ`card_sales.net_deposit_amount` where stage≠`deposited`로 대시보드 ④에 연결.

### UX 원칙 충족 (관리자 3클릭, 자동분류)
- 추천 매칭(💡)을 일괄 확정 1클릭으로 처리. 한 번 분류한 거래처는 규칙화되어 재입력 불필요 → 매월 매칭 부담 최소화.

```
┌──────────────────────────────────────────────────────────────────────────┐
```

### 구성요소 · 데이터소스 · 산식
- 상단 KPI = `revenue_records`(선택 basis 합) / `expense_records` 합 / 영업이익 = 순매출−총비용, 영업이익률 = 영업이익÷순매출(§4.4).

- 유입경로별 = `revenue_records.marketing_source`별 매출 + CAC(광고비÷신규회원) + 전환율(§19).
- 회원지표 = LTV/재등록률/CAC(§19). 월말 예상 = 진행률 기반 추정(2차).

### 인터랙션
- **매출기준 토글** `«결제기준/소진기준»`이 화면의 1급 컨트롤. 강사·수업유형별 분해는 소진기준에서만 활성(§4.3: 결제기준은 상품 단위라 분해 불가)임을 라벨로 안내.
- 카드 클릭 → 드릴다운(예: 강사 → 해당 강사 세션·정산 목록).

### UX 원칙 충족 (원장 10초 · 비전문가)
- 상단 3개 KPI에 산식 라벨("순매출=총매출−환불", "영업이익=순매출−총비용")을 붙여 회계 지식 없이 이해. 결제기준/소진기준 토글 하나로 "현금흐름 관점"과 "수업 원가 관점"을 즉시 전환.

### 구성요소 · 데이터소스

- 정원 만석 → `[대기신청]`(`waitlists`). 마감 → 예약불가.

### 인터랙션 · 정책
- `[예약하기]` → 정책 검사: `booking_open_days`(14일 내), `booking_close_minutes`(시작 60분 전 마감), `daily_booking_limit`(1일 1회), 잔여>0 → `reservations`(is_self_booked=true) 생성. 차감시점이 `on_booking`이면 즉시 `pass_transactions`(reason=`deduct_booking`).
- `[대기신청]` → `waitlists`(position 부여). 결원 시 `waitlist_auto_promote`로 자동 확정 + `notifications`(type=`waitlist_promoted`).
- 예약 완료 시 `notifications`(type=`reservation_done`) 발송.

### UX 원칙 충족 (회원 30초)
- 로그인→날짜 선택(기본 오늘)→`[예약하기]` 1탭으로 완료. 잔여횟수·취소마감을 항상 노출하여 추가 확인 불필요. 만석은 대기신청으로 자연 전환.

- `[취소]` → 취소마감 이내면 무차감 `reservations.status`=`canceled`(+ `restore_cancel` 복구 시 `pass_transactions`). 마감 이후면 `late_cancel_deduct`=true 정책에 따라 차감 유지.
- `[정지신청]` → `passes.pass_status`=`paused`, `paused_at` 기록(관리자 승인 흐름은 정책에 따름, §15).
- 회원에게는 **본인 데이터만** 노출(다른 회원·매출·통장 정보 일절 비노출, §5).

### UX 원칙 충족 (회원 30초 · 권한 분리)
- 수강권·예약·결제를 한 스크롤에 통합. 취소는 마감 이전에만 버튼이 보여 정책 위반 시도 자체를 차단. 본인 데이터 외 접근 원천 차단으로 개인정보 보호.
