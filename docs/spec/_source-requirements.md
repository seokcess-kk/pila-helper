# 원본 요구사항 (정본 소스) — 필라테스 경영관리 SaaS

> 이 문서는 제품 오너가 제시한 **원본 요구사항 전문**이다. `docs/spec/` 의 모든 설계 산출물은
> 이 문서와 `00-canon.md`(단일 진실원천)를 근거로 작성·검증된다. 임의 변경 금지(정본).

## 역할/관점

시니어 프로덕트 매니저 · SaaS 서비스 기획자 · UX 설계자 · 회계/정산 로직에 강한 풀스택 아키텍트의 관점으로 설계한다.

## 배경

새로 오픈하는 필라테스 샵을 위한 자체 운영 솔루션. 초기에는 내부 샵 운영용, 이후 여러 샵이 쓰는 **SaaS형 솔루션**으로 확장.

벤치마크: **스튜디오메이트, 바디코디, 아하루**. 단순 복제 금지. 예약·회원권·수업관리·출석·강사관리의 장점은 참고하되,
우리 솔루션은 특히 **"수익분석"과 "경영관리"** 를 강하게 가져간다.

## 최종 콘셉트

> **"필라테스 샵을 위한 예약·회원권·출석·상담CRM·매출·비용·수익분석 통합 경영관리 솔루션"**

## 핵심 목표

1. 1:1 개인레슨과 그룹레슨 운영을 하나의 시스템에서 관리.
2. 회원은 모바일 웹에서 직접 예약·취소·대기 신청.
3. 원장/관리자는 회원권 잔여횟수·만료일·출석·결석·노쇼·미수금을 한눈에.
4. 상담 고객 → 체험수업 → 회원권 등록 전환 과정을 CRM으로 관리.
5. 현장 카드결제 + 무통장입금/계좌이체 중심의 초기 결제 구조 지원.
6. 추후 온라인 결제·PG·오픈뱅킹·카드매출 조회·알림톡·전자계약·SaaS 과금까지 확장 가능 설계.
7. 원장이 이번 달 매출·비용·영업이익·현금흐름·카드 미입금액·미수금·월말 예상 수익을 쉽게 확인.
8. 사업자 통장 입출금·사업자 카드 사용 내역 기반으로 수입/지출 트래킹·자동 분류.

## 사용자

1. 원장/오너 2. 관리자/인포 직원 3. 강사 4. 기존 회원 5. 신규 상담 고객 6. (향후) SaaS 관리자

## 운영 조건

- 수업 유형: 1:1 개인레슨 + 그룹레슨 중심.
- 회원권: **횟수권 중심**.
- 초기 결제: 현장 카드결제 + 무통장입금/계좌이체 중심.
- 회원용 앱은 초기엔 없음 → **모바일 웹 예약 페이지**로 시작.
- 온라인 결제는 2~3차 기능.
- 초기엔 내부 샵용이지만 데이터 구조는 **반드시 SaaS 확장 가능**하게 설계.

### 18. UX 원칙
- 원장: 대시보드에서 오늘 운영 + 이번 달 수익을 **10초** 안에 파악.
- 관리자: 회원 등록/예약 변경/수강권 부여/결제 입력을 **3번 클릭** 안에.
- 회원: 모바일 웹에서 예약을 **30초** 안에 완료.
- 수익분석 화면은 회계 지식 없어도 이해 가능.
- 통장/카드 내역은 자동분류하되 관리자가 쉽게 수정 가능.
- 한 번 수정한 거래처 분류는 다음 거래부터 자동 적용.
- 결제 기준 매출과 수업 소진 기준 매출을 구분 표시.
- 개인/결제/수익 정보는 권한별 엄격 제한.
- 모든 금전 관련 수정은 로그.

## 주의사항

- 기존 솔루션의 UI/문구/구조를 그대로 복제하지 않는다.
- 필라테스 신규샵의 실제 운영 흐름에 맞게 기능을 단순화한다.
- 초기 버전은 **관리자 웹 + 회원용 모바일 웹** 중심.
- 앱/출입제어/키오스크/온라인 결제/오픈뱅킹/카드매출조회는 확장 기능.
- 초기 MVP에서도 데이터 구조는 SaaS 확장 + 금융 연동 고려.
- **수익분석은 이 솔루션의 핵심 차별화 기능이므로 가장 중요하게 다룬다.**
- 회계 전문용어보다 원장이 이해하기 쉬운 표현.
- 개인/금융/결제/매출/비용 정보는 보안·권한 분리 최우선.
