# 07-ia.md — 화면 정보구조(IA)

> **목적**: 관리자 웹과 회원 모바일웹 두 사이트의 전체 사이트맵(트리)·권한별 메뉴 노출 매트릭스·네비게이션 원칙을 확정하여, 와이어프레임([`08-wireframes.md`](./08-wireframes.md))·화면별 API([`12-api.md`](./12-api.md))·권한 구현([`13-rbac.md`](./13-rbac.md))의 기준 골격을 제공한다.

본 문서는 [`00-canon.md`](./00-canon.md)의 역할(§3.18 `role` 7종)·리소스(§2 엔티티)·RBAC 스켈레톤(§5)·정책 파라미터(§6)를 **글자 단위로** 따른다. 화면명/메뉴명은 한글 라벨이되, 각 화면이 다루는 리소스·enum은 모두 CANON 코드값을 근거로 표기한다. 본 문서는 정의를 신설하지 않으며 CANON을 화면 골격으로 **시각화·구성**만 한다.

- 대상 사이트: **(A) 관리자 웹**(데스크톱 우선, 반응형) · **(B) 회원 모바일웹**(모바일 우선, 앱 없음 — 원본 운영조건 "회원용 앱 초기 없음 → 모바일 웹 예약 페이지로 시작")
- 멀티테넌시: 모든 화면은 로그인 사용자의 `tenant_id` + `studio_id` 범위 안에서만 데이터를 보여준다. `saas_admin`만 테넌트 경계를 넘는 SaaS 콘솔(§A-11)에 접근한다.

## 1. IA 설계 원칙 (Navigation Principles)

원본 §18(UX 원칙)을 IA 규칙으로 번역한다.

| # | 원칙 | IA 적용 규칙 |
|---|---|---|
| P1 | 원장은 **10초** 안에 오늘 운영 + 이번 달 수익 파악 | 로그인 직후 첫 화면 = **대시보드**(§A-1). 4영역(오늘운영/매출/비용/수익)을 스크롤 없이 1뷰. 수익분석 진입은 1클릭. |
| P2 | 관리자는 회원 등록/예약/수강권/결제를 **3클릭** 안에 | 모든 핵심 생성 액션은 글로벌 상단 **+ 빠른등록** 버튼에서 2클릭 내 진입. 깊이 ≤ 3단(구역 → 목록 → 상세/모달). |
| P3 | 회원은 모바일웹에서 예약을 **30초** 안에 | 회원 모바일웹 첫 화면 = **예약(타임테이블)**. 예약 완료까지 탭 3회(회차 선택 → 수강권 확인 → 예약확정). |
| P4 | 수익분석은 회계 지식 없어도 이해 | 수익분석 구역(§A-8)은 항상 **결제기준/소진기준 토글**(`revenue_basis`)을 상단 고정. 용어에 한글 설명 툴팁. |
| P5 | 통장/카드 자동분류 + 쉬운 수정 | 비용·매칭 구역(§A-6)은 "미매칭 큐"를 최상단 노출. 분류 수정은 인라인. 한 번 수정한 규칙은 다음 거래부터 자동(`transaction_matching_rules`). |
| P6 | 결제기준 vs 소진기준 구분 표시 | 매출·수익 관련 모든 위젯에 인식기준 라벨 명시. 두 기준 값을 한 화면에서 혼합 합산 금지(§00-canon §4.3). |
| P7 | 개인/결제/수익 정보 권한별 엄격 분리 | **메뉴 자체를 권한으로 가린다**(메뉴 클로킹). 강사는 전체 매출·통장 잔액 메뉴 미노출(§5: 통장 잔액 강사 "불가"). 회원은 본인 데이터 화면만. |
| P8 | 모든 금전 수정은 로그 | 결제/환불/수강권 차감/거래 매칭 화면에는 "변경 이력"(`audit_logs`) 탭/링크 상시 제공. |

### 1.1 글로벌 네비게이션 규칙

- **관리자 웹**: 좌측 1뎁스 **사이드바**(구역) + 상단 **글로벌 바**(스튜디오 선택 · 전역검색 · + 빠른등록 · 알림 · 계정). 구역 진입 시 2뎁스는 상단 **탭** 또는 좌측 서브메뉴.
- **스튜디오 스위처**: 상단 글로벌 바에 둔다. 단일 지점 테넌트는 표시만, 다지점(3차)·`saas_admin`은 전환 드롭다운. 전환은 `studio_id` 컨텍스트만 바꾸며 화면 구조는 동일.
- **회원 모바일웹**: 하단 **탭바 3개**(예약 · 마이 · 알림) 고정. 깊이 ≤ 2단. 좌상단 뒤로가기만, 사이드바 없음.
- **빈/권한 없음 처리**: 권한 없는 화면은 **메뉴에서 숨김**(노출 후 차단이 아니라 비노출). 직접 URL 접근 시 403 화면.
- **딥링크**: 알림(SMS/카카오) → 모바일웹 해당 예약/수강권 상세로 딥링크. 관리자 알림 클릭 → 해당 회원/결제 상세.

## 3. (B) 회원 모바일웹 — 사이트맵 (트리)

회원(`member`)은 **본인 데이터만**(§5: 회원 = own). 하단 탭바 3개로 단순화하여 30초 예약(P3) 달성. 로그인은 휴대폰 인증 또는 이메일/비밀번호(`users.role=member`, `member_id` 연결).

```

│
├─ [하단 탭바] 예약 · 마이 · 알림
│
├─ B-1. 예약 (/m)  ※첫 화면                                  [class_sessions, reservations, waitlists, passes]
│   ├─ 타임테이블(날짜 스와이프·공개 수업만 is_public) (/m/schedule)  [class_sessions ◆session_status=open]

│
├─ B-2. 마이페이지 (/m/my)                                   [passes, reservations, attendance, members]
│   ├─ 내 수강권(권종/잔여횟수/만료일/정지여부) (/m/my/passes)       [passes ◆pass_status]
│   │   └─ 수강권 상세(사용 이력 = 차감 내역)                       [pass_transactions(read own)]
```

## 4. 권한별 메뉴 노출 매트릭스 (Menu Visibility)

CANON §5(RBAC 스켈레톤)와 §3.18(role 7종)을 **메뉴 노출 규칙**으로 환산한다. 셀 값 의미:

- **●** = 메뉴 노출(화면 진입 가능, 구역 내 액션은 §5 RBAC가 추가 제한)
- **◐** = 부분 노출(읽기 전용 또는 일부 탭/스코프만; 비고에 한정 명시)
- **○** = 메뉴 비노출(클로킹; 직접 URL 접근 시 403)
- 스코프: `all`(스튜디오 전체) / `assigned`(담당) / `own`(본인)

#### 4.1.1 통장 잔액 — 강사 차단 명시 (P7)

CANON §5는 "통장 잔액 — instructor **불가**"를 명시한다. IA 적용:

- A-7(비용·거래매칭) 구역 자체를 instructor에게 비노출(○).
- A-1 대시보드 ④수익영역, A-8 수익분석의 "현금흐름(통장잔액·미입금카드매출)" 위젯은 instructor에게 렌더링하지 않는다(부분 노출 ◐의 매출-only 한정).
- 강사가 보는 매출은 `revenue_records` 중 `instructor_staff_id = 본인`인 assigned 매출로만 필터(§5 "수익분석 — instructor R(assigned 매출만)").

## 8. 상태(상태머신) 진입점 요약 — IA 관점

화면에서 사용자가 트리거하는 주요 상태 전이의 **진입 화면**을 명시한다(상태값 정의·전이 규칙은 각 정책 문서 소유).

| 상태 enum | 진입 화면 | 주요 전이 |
|---|---|---|
| `member_status` (§3.1) | A-3 회원 / A-4 CRM | new_inquiry→…→enrolled→(dormant/expired)→re_enrolled |
| `lead_status` (§3.2) | A-4 CRM 칸반 | new_inquiry→contacted→trial_booked→trial_done→enrolled |
| `reservation_status` (§3.5) | A-2 회차 패널 / B-1 | booked→(attended/no_show/canceled), waitlisted→booked |
| `attendance_status` (§3.6) | A-2 출석체크 | attended/late/absent/no_show/excused |
| `pass_status` (§3.8) | A-5 수강권 | active→(paused/expired/refunded/used_up) |
| `payment_status` (§3.10) | A-6 결제 | awaiting_deposit→partial→paid / receivable / refunded |
| `reconciliation_stage` (§3.21) | A-7 카드매출 대조 | approved→captured→deposited |
