# 00-index.md — 마스터 인덱스 (Master Index)

> **이 문서는 `docs/spec/` 전체의 길잡이다.** 한 줄 제품 정의부터 24개 산출물(정본 소스 + 단일 진실원천 + 23 산출물) 색인, 역할별·목적별 추천 읽기 순서, 핵심 차별화 안내, 문서 간 의존관계까지 한 화면에서 잡는다.
> 모든 정의(스키마·enum·RBAC·회계모델·정책 기본값)의 **단일 진실원천(SSOT)** 은 [`00-canon.md`](./00-canon.md)이며, 그 근거 정본은 [`_source-requirements.md`](./_source-requirements.md)이다. 본 인덱스는 **탐색용 메타문서**로, 정의를 신설하지 않는다. 충돌 시 `00-canon.md`가 우선한다.
> **문서 버전**: v1.0 / 기준일 2026-06-12

---

## (a) 한 줄 제품 정의

> **"필라테스 샵을 위한 예약·회원권·출석·상담CRM·매출·비용·수익분석 통합 경영관리 솔루션(SaaS)."**

다른 예약 솔루션이 "수업을 돌리는 도구"라면, 본 솔루션은 거기에 더해 **"이번 달 우리 샵이 실제로 얼마를 벌고 있는가"를 회계 지식 없이도 답해 주는 경영 도구**다. 운영은 빠르게(원장 10초·관리자 3클릭·회원 30초), 돈은 정확하게(**이중기준 손익** + **통장/카드 매칭**), 확장은 처음부터(멀티테넌트 SaaS).

## (d) 핵심 차별화 — 이중기준 손익 · 통장/카드 매칭

> 예약·출석·수강권은 "있어야 하는 기본기"이고, 경쟁 우위는 **돈을 다루는 방식**에 있다. 두 축이 핵심 차별화이며 가장 중요하게 설계된다(원본 §18·주의사항, canon §4·§3.21).

### 차별화 A — 결제기준 + 수업소진기준 **이중 손익**

같은 한 건의 결제를 **두 회계 기준으로 동시에 인식**하고 대시보드에서 토글한다. 모든 인식은 `revenue_records`에 `revenue_basis`(`payment`/`consumption`)로 분리 적재된다.

- **결제 기준(`payment`)** — "**돈이 들어온 날** 번 것으로 친다." 현금흐름·자금관리에 유리. 결제 시 1건(+환불 음수 1건).
- **수업 소진 기준(`consumption`)** — "**수업을 쓴 만큼** 번 것으로 친다." 원가·강사료·수익성 분석에 유리. 차감 시마다 N건.
- **단가 산식**: `passes.unit_price_amount = round(purchases.final_amount / passes.total_count)`(발급 시 고정).
- **불변 규칙**: 두 기준을 **합산하지 않는다**(이중 합산 금지). 기준별로만 SUM한다.
- 예: 60만원/10회권을 6월에 결제·3회 출석 → 결제기준 **600,000원**, 소진기준 **180,000원**(둘 다 맞다, 질문이 다를 뿐).
- 소유: 모델 [`00-canon.md`](./00-canon.md) §4 · 산식 [`19-metrics.md`](./19-metrics.md) · 화면 [`10-profit-dashboard.md`](./10-profit-dashboard.md).

### 차별화 B — 통장/카드 기반 **현금흐름·자동 매칭**

사업자 통장 입출금·카드 사용/매출 내역을 시스템으로 가져와 **매출/비용/이체/기타로 분류**하고, 거래처명 규칙으로 **한 번 고친 분류를 다음 거래부터 자동 적용**한다.

- **카드매출 3단계 추적**(`reconciliation_stage`: `approved`→`captured`→`deposited`): "승인≠매입≠입금" → **미입금 카드매출** = Σ`card_sales.net_deposit_amount` where `stage != deposited`.
- **입금 매칭**: 입금자명↔회원명 자동추천(금액/날짜/이름 스코어링) → `payments` 연결(미수/입금대기 해소).
- **자동분류 학습**: 거래처명 규칙(`transaction_matching_rules`) → `expense_category`(17종)+`cost_type`(고정/변동) 자동 분류.
- 단계 경계: **MVP는 CSV 업로드 + 수동 분류**, **자동분류·자동매칭은 2차**, **오픈뱅킹·카드조회 실연동은 3차**.
- 소유: [`17-reconciliation-policy.md`](./17-reconciliation-policy.md) · [`18-expense-category-policy.md`](./18-expense-category-policy.md) · 화면 [`08-wireframes.md`](./08-wireframes.md)(화면 11).

## 남은 이슈 (스텁/누락/모순 점검)

> `docs/spec/`의 24개 .md를 전수 검토한 결과. **치명적 누락·스텁·모순은 발견되지 않았다**(산출물 1~23 전부 실체 있는 본문 보유, enum/테이블 명칭이 문서 전반에서 글자 단위로 일치). 아래는 **개선 권고 수준의 경미한 정합성 메모**다. 모두 비차단(non-blocking)이며, 출시 게이트를 막지 않는다.

1. **[경미·표기] 테이블 "수" 카운트 표현 혼선** — `00-canon §2` 말미 점검 문구에 "43 정의"라는 중간 표현이 등장하나(도메인 합산 설명 과정), 동일 절의 §16 대조표와 `11-erd §2` 인벤토리는 모두 **42개**로 확정한다. 최종 수치(42)는 일관되며 실제 테이블 누락은 없다. 카운트 설명 문구만 "42"로 통일하면 혼선이 줄어든다.

2. **[경미·표기] enum 사전 번호 공백(§3.15)** — `00-canon §3.15`는 "예약 — `class_type`은 §3.3 단일 정의를 공유한다"는 안내만 있고 독립 enum이 없다(의도된 자리표시). 번호는 채워져 있어 누락이 아니나, 빈 절처럼 보일 수 있다.

3. **[경미·정합] 알림 유형 "13종 vs 14종" 라벨** — 원본/canon은 `notification_type`을 "13종"으로 칭하지만 `00-canon §3.20` 표에는 `counseling_reminder`를 포함해 **14개 코드**가 정의되어 있다. `04-feature-catalog §M12`가 "상담 리마인드 포함 시 14종"으로 이미 주석을 달아 정합을 맞춰 두었다. 명칭만 "13+1"임을 canon 본문에도 한 줄 못 박으면 더 명확하다.

4. **[경미·정합] 환불 위약공제 단가 기준 예시 차이** — 환불 산식에서 사용분 공제 단가를 `refund_unit_basis`(기본 `list_price`=정가)로 잡는다(canon §6.3). `03-scenarios §10-B`·`05-scope-mvp US-G3`는 "정가=실판매가" 가정이라 정가/실판매가 단가가 같지만, `08-wireframes` 발급 예시(정가 360,000·할인 후 350,000)처럼 **할인이 있는 경우** 두 단가가 달라진다. 산식 자체는 `16-payment-refund-policy`가 정본으로 일관되나, 예시 수치가 문서마다 가정이 달라 빠르게 비교하면 어긋나 보일 수 있다(실제 모순 아님, 가정 차이).

5. **[경미·범위 경계] 대기 자동전환·자동폐강의 단계 태그** — `03-scenarios §3`·`08-wireframes`는 대기 자동전환을 기본 동작처럼 서술하나, `04-feature-catalog`는 F-03-11(자동 폐강)·F-03-12(대기 자동전환)을 **2차**로 태그한다. MVP에서는 "후보 표시 + 수동 처리/인앱 표시"까지이고 완전 자동화는 2차임을 `05-scope-mvp`(US-C3·US-D4)가 정리해 두었다. 시나리오/와이어프레임을 빠르게만 보면 MVP 자동화로 오해할 수 있어, 해당 화면 캡션에 단계 배지를 다는 정도의 보강이 가능하다.

6. **[정보·구조] 대용량 문서 2건** — `11-erd.md`(약 1,256줄)·`12-api.md`(약 1,420줄)는 단일 파일로 매우 길다. 내용 누락은 아니나(전 테이블·전 리소스 수록), 향후 유지보수 편의를 위해 도메인별 분할 또는 목차 앵커 보강을 고려할 수 있다.

**결론**: 6건 모두 **표기·예시·구조 수준의 경미 사항**으로, 정의 충돌(canon 위반)이나 산출물 누락은 없다. 23개 산출물 + 정본 소스 + SSOT가 모두 실체 있게 완비되어 있으며, 핵심 차별화(이중기준 손익·통장/카드 매칭)는 `00-canon §4`·`10`·`17`·`18`·`19`에서 일관되게 정의·시각화·산식화되어 있다.
