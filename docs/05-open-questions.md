### C-7 근거 (클라이언트 전략 분석)
- "반응형 웹 단일"과 "회원/운영자 분리"는 별개 축: **코드베이스(단일)** + **역할 기반 뷰 분기**로 해결.
- 운영자: 타임테이블·손익은 큰 화면 유리 → 반응형이 PC에서 잘 동작하면 충분. (아하루는 운영자 **PC 웹 전용** → 우리는 반응형이라 **폰에서도 손익 확인** 가능 = 오히려 우위)
- 회원: 예약·알림은 폰. 모바일 웹도 가능하나 재방문/푸시/홈아이콘은 앱이 유리 → **PWA로 보완**(설치, 웹푸시 iOS 16.4+). 네이티브는 리텐션 증명 후.
- 결론: 사용자 직관(반응형 웹 단일) 채택. **하나의 제품, 역할별 다른 화면.**

## (참고) 전체 질문 목록

## A. 타겟 & 범위
1. **주 타겟 규모**: 1인 1룸 / 2~3룸 소수강사 / 다강사 중형 — 어디에 1차 집중?

3. 1차 출시 지역/채널: 직접 영업? 커뮤니티/카페? 기존 인맥?

## B. 차별화(손익) 깊이
4. **자동연동 우선순위**: MVP부터 'CSV 업로드 자동분류'로 가고, 자동연동은 v1으로 미루는 안에 동의?

6. 세무(예상세금/세무사 연동)까지 갈 것인가, 손익 가시화에서 멈출 것인가?

## C. 제품 형태
7. **앱 형태**: 네이티브 앱 vs PWA/반응형 웹 (MVP는 웹 권장 — 빠른 검증)

9. 회원용/관리자용/강사용 **3-앱** 구조 vs 통합 1앱 권한분리?

## D. 비즈니스
10. **수익모델**: "예약 무료 + 손익/CRM 유료" 구조에 동의? 목표 객단가?
11. 경쟁사 대비 가격 포지션: 어시스트핏(무료) 의식 수준?
12. 출시 목표 시점 / 초기 파일럿 매장 확보 가능 수?

## E. 실행
13. **기술 스택** 선호(웹 프레임워크/DB/호스팅)? 개발 인력 규모?
