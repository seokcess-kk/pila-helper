# 03. 수익·비용 자동 리포팅 (통장/카드 연동) ★ 핵심 차별화

> "필라테스 사장님이 **이번 달 실제로 얼마 벌고 얼마 썼는지**를
> 엑셀/장부 없이 자동으로 보는 것" = 다른 솔루션이 안 하는 영역.

---

## 1. 왜 이 기능이 핵심인가

- 기존 솔루션의 '매출'은 **수강권 판매 기준(약정 매출)**일 뿐, 실제 **통장에 들어온 돈**과 다르다.
  - 예: 미수금, 환불, 일부 현금 직거래, 카드사 입금 지연 등으로 차이 발생.
- 비용(임대료·강사급여·기구 리스·소모품·공과금·세금)은 어디서도 자동 관리되지 않음 → 사장님은 **순이익(진짜 남는 돈)**을 모른다.
- 소상공인은 세무사를 써도 "월 단위로 내가 흑자인지 적자인지"를 실시간으로 못 본다.
- → **"예약 솔루션 + 작은 회계사"** 결합이 우리 해자(moat).
- **회계 기준 = 현금주의 단일**(수입=실입금, 비용=실지출). 약정매출(`sale`)은 영업지표로만, 손익 합산엔 미포함 → **이중계상 방지**. 상세 [06 §6.4](06-data-model.md).

---

## 2. 데이터 소스와 연동 방식

| 소스 | 무엇을 얻나 | 연동 방식(후보) | 난이도/제약 |
|------|------------|----------------|------------|
| **사업용 통장(입금)** | 회원 입금, 카드사 정산 입금 | 오픈뱅킹 API / 마이데이터 | 인증·제휴 필요(아래 3장) |
| **사업용 카드(지출)** | 임대료·소모품·공과금 등 | 마이데이터(카드사) / 명세서 업로드 | 카드사별 편차 |
| **★ 카드승인·입금 문자(SMS)** | 결제 즉시 비용/입금 자동 캡처 | **본인 기기 SMS/알림 파싱(라이선스 불필요)** | 안드로이드 가능 / iOS 제약 |
| **PG/결제대행 정산** | 카드 매출 정산 내역 | PG사 API(연동 시) | PG 도입 시 |
| **수기 입력 / 영수증** | 현금 거래, 누락분 | 직접 입력 / OCR | 보완용 항상 필요 |
| **자체 판매데이터** | 수강권 판매(약정 매출) | 내부 DB(2번 모듈) | 즉시 가능 |

> 설계 원칙: **"자동 연동 + 수기 보정"** 하이브리드. 100% 자동은 불가능하므로
> 자동으로 80%를 채우고, 사장님이 20%를 손쉽게 메우는 UX가 핵심.

## 3. 금융데이터 연동의 현실적 제약 (★ 반드시 검토)

> 한국에서 통장/카드 내역을 끌어오는 것은 **법·인증 이슈**가 있어 단계적 접근이 필요.

### (A) 마이데이터(본인신용정보관리업)
- 금융위 **허가**가 필요한 규제 사업. 직접 라이선스 취득은 스타트업에 부담.
- **현실 경로**: 마이데이터 인증 사업자/핀테크와 **제휴(API 재판매·중계)** 또는 데이터 표준 API 활용.

### (B) 오픈뱅킹
- 입출금 조회/이체 표준 API. 다만 **B2C 개인** 위주이고, 사업자 통장·기관 가입 요건 존재.
- 일부 인터넷전문은행(카카오/토스 등) 연동 편차 → 커버리지 확인 필요.

### (C) 대안/하이브리드 (MVP에서 현실적으로 권장)
1. **★ 카드승인·입금 문자(SMS) 자동 캡처** → 결제·입금 즉시 자동 등록. **라이선스 불필요**(본인 기기·동의 기반).
   - 플랫폼 한계: **안드로이드** = 알림/SMS 권한으로 파싱 가능 / **iOS** = SMS 자동읽기 불가 → 영수증 OCR·공유시트로 보완.
   - 한국 가계부앱이 검증한 방식. CSV보다 훨씬 "자동" 체감 → **MVP 차별화 wedge** + 마이데이터 제휴의 백업(단일 실패점 회피).
2. **명세서/거래내역 파일 업로드(CSV·엑셀)** → 파싱·자동 분류 (라이선스 불필요, 즉시 가능)
3. **수기 빠른 입력 + 반복거래 템플릿**(임대료처럼 매월 같은 항목 자동 생성)
4. 추후 제휴 확보 시 (A)/(B) 마이데이터·오픈뱅킹 자동 연동으로 승급

> 결론: **MVP는 "SMS캡처 + 업로드 + 수기"로 '자동 손익' 체감을 제공**(차별화를 MVP로 끌어옴) → v1에서 제휴 자동연동.
> 법무/금융 자문은 자동연동(A/B) 착수 전 필수. SMS캡처는 본인 기기·동의 기반이라 라이선스 불요(개인정보 처리방침엔 반영).

## 4. 핵심 개념: 거래(Transaction) 분류 엔진

모든 소스의 데이터를 하나의 **거래 원장(Ledger)** 으로 통합하고 자동 분류한다.

```
[원천: 통장입금 / 카드지출 / 판매데이터 / 수기]
        │
        ▼
   거래 정규화(날짜·금액·적요·수단)
        │
        ▼
   자동 분류 규칙 엔진  ◄─ 사장님이 만든 규칙 + 학습
        │
        ▼
   ┌─────────────┬──────────────┐
   수입(매출)        비용(지출)        이체/제외(사적·내부)
        │
        ▼
   월별 손익 = 수입 - 비용
```

### 수입(매출) 카테고리(예)
- 수강권 매출(개인/그룹), 상품판매, 기타

### 비용 카테고리(예)
- 임대료/관리비, 강사 급여, 4대보험/세금, 기구 리스·구입, 소모품(매트·양말 등),
  마케팅/광고, 공과금(전기·수도·통신), 카드수수료/PG수수료, 기타

### 분류 규칙 엔진
- **규칙**: "적요에 '○○부동산' 포함 → 임대료", "'배달의민족' → 식대(사적, 제외)" 등
- **반복거래**: 매월 1일 임대료처럼 정기 항목 자동 인식·확정
- **학습**: 사장님이 한번 분류하면 같은 거래처는 자동 적용
- **확인 큐**: 애매한 거래는 '검토 필요'로 모아 한번에 스와이프 확정

### 매칭 (자동 대사, Reconciliation)
- **판매데이터(약정 매출) ↔ 통장 입금** 자동 매칭 → 미수금/입금 확인
- 카드사 정산 입금은 합산 입금되므로 일자·금액 추정 매칭 + 수기 보정

## 5. 리포트 산출물 (사장님이 보는 것)

| 리포트 | 내용 | 단계 |
|--------|------|------|
| **이번달 손익 요약** | 수입 / 비용 / 순이익 / 전월 대비 | `[v1]` |
| 월별 추이 그래프 | 6~12개월 수입·비용·순익 트렌드 | `[v1]` |
| 비용 구성 분석 | 카테고리별 비중(임대 X%, 급여 Y%…) | `[v1]` |
| 수입 구성 분석 | 신규 vs 재등록, 상품별 | `[v1]` |
| 미수금/환불 현황 | 약정-실입금 차이 | `[v1]` |
| 강사 정산 리포트 | 강사별 급여(자동 정산값) | `[v1]` |
| 손익분기 안내 | "이번달 고정비 = N원, 목표 회원/매출" | `[v2+]` |
| 세무 내보내기 | 세무사 전달용/홈택스 참고용 | `[v2+]` |
| 예상세금(VAT 등) 가이드 | 과세유형별 추정 | `[v2+]` |

### 차별화 UX 아이디어
- **"이번 달, 지난달보다 ○○만원 더 남았어요/덜 남았어요"** 같은 한 줄 인사이트
- **비용 이상 감지**: "공과금이 평소보다 40% 증가했어요"
- **재등록이 순익에 미치는 영향**을 예약 모듈과 연결해서 제시

## 6. 데이터 모델 스케치 (개념)

```
Studio(매장)
 └─ Account(연동 계좌/카드)  ─< Transaction(거래원장)
                                   ├─ direction: income|expense|transfer
                                   ├─ category, ruleId, source
                                   ├─ matchedSaleId? (판매 대사)
                                   └─ status: auto|reviewed|confirmed
 └─ Sale(판매: 수강권/상품)   ─ 약정매출
 └─ Expense(비용)            ─ 수기/자동
 └─ Payroll(강사 정산)       ─ 비용으로 편입
 └─ FinancePeriod(월 마감)   ─ 손익 스냅샷
```

## 7. 단계별 실행 (이 기능 한정 로드맵)

- **Phase 0 (MVP)**: **카드/입금 문자(SMS) 자동캡처** + 수기 비용입력 + 판매매출 집계 + 거래내역 CSV 업로드 + **월 손익 요약(현금주의)**. 분류는 수동+반복 템플릿(규칙 자동학습은 v1).
- **Phase 1 (v1)**: 제휴 기반 **오픈뱅킹/마이데이터 자동연동**, 자동 대사, 강사정산 편입, 추이/구성 리포트
- **Phase 2 (v2+)**: 세무 내보내기, 예상세금, 손익분기/목표관리, 이상감지 인사이트

> ⚠️ 자동연동(Phase 1) 진입 전 **법무·금융 컴플라이언스 검토 필수**.
> MVP는 라이선스 없이 가능한 "업로드+수기"로 **가치부터 증명**.
