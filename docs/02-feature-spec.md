# 02. 기능 명세 (Feature Spec)

> 범위: 벤치마크에서 도출한 "표준 기능(A)" + "차별화 기능(B)"을 모듈로 정리.
> 표기: `[MVP]` 1차 출시 / `[v1]` 정식판 / `[v2+]` 이후. `★` = 차별화 핵심.

---

## 모듈 맵 (전체 구조)

```
필라헬퍼 — 한 앱 · 역할기반 뷰 · 운영/재무 구역 분리 (D-6)

◆ 운영 콘솔 (CRM+예약) — owner + staff(v1)
├── 8. 운영 대시보드 (오늘 예약·노쇼·만료) ──[손익 브리지]──┐
├── 1. 회원 관리 (Member)                                    │
├── 2. 예약 / 스케줄 (Booking)                               │
├── 3. 수강권 발급·판매 (Pass & Payment)  ← 판매 '행위'       │
├── 4. 수업 / 강사 (Class & Instructor)                      │
└── 6. 알림 / 메시지 (Notify & CRM)                          │
                                                            ▼
◆ 재무 / 경영 어드민 — owner 전용 🔒
└── 5. 매출·비용·손익 (Finance) ★  ← 매출 '분석'·SMS큐·미수금·정산

◆ 설정
└── 7. 매장·수업·수강권상품·강사·정책

◆ 회원앱 — member 뷰
└── 9. 예약 / 마이페이지
```

> **구역 분리(D-6)**: 같은 앱·같은 데이터 레이어. **재무는 owner 전용 별도 구역**으로 격리(권한·민감도),
> 운영 대시보드의 **손익 브리지**로 연결해 통합 인사이트(해자)는 유지. 판매 '행위'=운영(회원360° 발급) /
> 매출 '분석'=재무. `sale` 데이터는 하나, 보는 면만 다름.

## 1. 회원 관리 (Member) — 관리자 사이드 × 회원 사이드

> 2대 핵심 기둥. 양면 전체 생애주기 상세는 **[07-member-management.md](07-member-management.md)**. 아래는 요약.

### 1-A. 관리자 사이드 (운영자/강사)
| 기능 | 단계 | 설명 |
|------|------|------|
| 회원 유입·등록 | `[MVP]` | **운영자 초대 등록**·엑셀 일괄 / 셀프가입·데이터이전은 `[v1]` |
| 등록 대기 승인 큐 | `[v1]` | 셀프가입 회원 승인·거절, 중복(번호) 병합 |
| 회원 360° 상세 | `[MVP]` | 수강권·예약/출석·결제/미수금·메모/상담 한 화면 + 즉시 발급 |
| 검색·필터·세그먼트 | `[MVP]` | 수강권상태·등록일·활성/휴면·태그 |
| 회원 상태 자동 태깅 | `[v1]` | 활성/휴면/만료임박/이탈위험 |
| 상담·리드 관리 | `[v1]` | 상담일정 → 회원 전환 추적 |
| 태그 / 동의 / 권한별 노출 | `[v1]` | VIP·재활 태그, 동의이력, 강사=담당회원만 |

### 1-B. 회원 사이드 (수강생 셀프서비스)
| 기능 | 단계 | 설명 |
|------|------|------|
| 가입·온보딩 | `[MVP]` | 초대링크/QR, 휴대폰 인증, 번호 매칭 자동연결 |
| 마이페이지 | `[MVP]` | 내 수강권(잔여/유효)·결제내역·예약현황 |
| 내정보·계정 관리 | `[MVP]` | 프로필 수정, 비번 변경, 탈퇴 |
| 예약/취소/대기 | `[MVP]` | 예약 모듈 연결, 잔여 기반 예약가능 표시 |
| 가입 시 약관·개인정보 동의 | `[MVP]` | 법적 필수. 동의 이력·마케팅 토글은 `[v1]` |
| 알림 설정 / 1:1 문의 | `[MVP]` | 예약·리마인더·수강권·공지 ON/OFF |
| 출석이력·내 운동기록 | `[v1]` | 운동기록·동의관리, 멀티센터 `[v2+]` |

## 2. 예약 / 스케줄 (Booking)

| 기능 | 단계 | 설명 |
|------|------|------|
| 주간/일간 타임테이블 | `[MVP]` | 룸·강사·시간대별 보기, 드래그로 수업 생성 |
| 예약/예약대기/취소/폐강 | `[MVP]` | 상태 실시간 반영 |
| 회원 셀프 예약(앱) | `[MVP]` | 정원/대기 자동, 잔여 좌석 표시 |
| 예약 정책 | `[MVP]` | 취소 마감, 당일변경, 노쇼차감, **예약 오픈/마감·1일 한도** |
| **예약 자격 검증** | `[MVP]` | 유효 수강권·잔여·scope·중복·마감·정원 → 규칙 [06 §6.1] |
| **차감 시점 정책** | `[MVP]` | 예약 시 vs 출석 시 차감 선택 [06 §6.2] |
| 정원/대기 자동 승급 | `[v1]` | 취소 발생 시 대기자 자동 승급 + 알림 |
| 반복 수업 생성 | `[v1]` | 매주 동일 스케줄 일괄 생성 |
| 출석 체크 / 자동 차감 | `[MVP]` | 출석 시 수강권 1회 차감, 노쇼 처리 |
| 휴강/공휴일/강사 휴무 | `[v1]` | 운영 캘린더와 연동, 영향 예약 일괄 처리 |
| QR/키오스크 체크인 | `[v2+]` | 소형은 후순위 (하드웨어 비의존 원칙) |

## 3. 수강권 / 결제 (Pass & Payment)

| 기능 | 단계 | 설명 |
|------|------|------|
| 수강권 상품 정의 | `[MVP]` | 개인/그룹, 회차권/기간권/혼합, 가격·유효기간 |
| 수강권 판매/등록 | `[MVP]` | 회원에게 발급, 시작일/만료일 자동 |
| 잔여·만료 관리 | `[MVP]` | 잔여 횟수/만료일 자동 계산·표시 |
| 일시정지(홀딩) | `[MVP]` | 부상/여행 등 기간 정지, 만료일 자동 연장 |
| 단순 환불 / 양도 | `[MVP]`/`[v1]` | 단순환불(상태·금액)=MVP, 부분환불 계산·양도=v1 |
| 미수금 관리 | `[MVP]` | 선등록 후 미결제 추적 (sale−실입금) |
| 결제수단·현금영수증 기록 | `[MVP]` | 카드/현금/이체/간편결제 + 현금영수증 발행 체크 (수기 OK) |
| PG 결제 연동 | `[v2+]` | 앱 내 카드결제 (선택) |
| 전자계약서/서명 | `[v2+]` | 등록 시 약관 전자서명 |

> 핵심: 여기의 "판매 매출"은 **5번 손익 리포팅의 '수입' 소스**와 연결된다.

## 비기능 요구사항 (NFR) — 초안

- **온보딩 5분**: 매장·수업·수강권만 넣으면 바로 예약 오픈
- **개인정보/보안**: 회원 민감정보(건강기록) 암호화, 동의 이력, 접근권한
- **금융데이터**: 마이데이터/오픈뱅킹은 인증 사업자 연동 또는 제휴 필요(법적 검토) → [03 문서](03-finance-reporting.md)
- **모바일 우선**: 사장님 80%가 폰으로 확인
- **확장성**: 1인 1룸 ~ 다강사 다룸 까지 동일 코어
